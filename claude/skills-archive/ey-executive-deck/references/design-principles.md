# Design Principles for Executive Presentations

Design serves the message. Every visual choice should amplify clarity, not add decoration.

---

## The Golden Rules

### 1. One Idea Per Slide

**The discipline:** Each slide makes exactly one point. If you find yourself using "and" or "also," split the slide.

**Why it matters:** Executives scan. When multiple ideas compete, none land.

**Test:** Cover everything except the headline. Can someone understand the slide's purpose? Now cover the headline. Does the content support exactly that one point?

### 2. Headlines Carry the Message

The headline isn't a topic label—it's the takeaway.

| ❌ Weak (Labels) | ✅ Strong (Asserts) |
|------------------|---------------------|
| "Customer Feedback" | "Customers Rate Us 4.7/5 but Want Faster Support" |
| "Financial Performance" | "Revenue Up 18% While Margins Held Steady" |
| "Market Trends" | "AI Adoption Accelerated 3x Faster Than Projected" |
| "Risk Assessment" | "Three Risks Require Immediate Mitigation" |

**Headline formula:** [Subject] + [Verb] + [Specific Outcome/Insight]

### 3. Progressive Disclosure

Layer information from essential to supporting:

```
┌─────────────────────────────────────────────┐
│  HEADLINE (Essential insight)               │
├─────────────────────────────────────────────┤
│                                             │
│     MAIN VISUAL OR KEY DATA                 │
│     (Supporting evidence)                   │
│                                             │
├─────────────────────────────────────────────┤
│  Footnote/source (Reference only)           │
└─────────────────────────────────────────────┘
```

Viewers should get 80% of the value from headline + main visual. Details are for those who want to dig deeper.

## Layout Principles

### Visual Hierarchy

Create clear levels of importance:

| Level | Element | Treatment |
|-------|---------|-----------|
| 1 | Headline | Largest, boldest, top of slide |
| 2 | Key insight/data | Large, prominent, center stage |
| 3 | Supporting points | Smaller, grouped, secondary position |
| 4 | Sources/footnotes | Smallest, bottom, gray text |

### The Grid

Use consistent alignment. The eye follows structure.

```
┌─────────────────────────────────────────────┐
│ HEADLINE ZONE                               │
├────────────────────┬────────────────────────┤
│                    │                        │
│   LEFT CONTENT     │    RIGHT CONTENT       │
│                    │                        │
├────────────────────┴────────────────────────┤
│ FOOTNOTE ZONE                               │
└─────────────────────────────────────────────┘
```

**Common patterns:**
- 50/50 split: Compare two things
- 60/40 split: Main content + supporting sidebar
- Full width: Single dominant visual
- Thirds: Three equal elements

### White Space

White space isn't empty—it's strategic.

**Minimum margins:** 0.5" on all sides
**Between elements:** Consistent gutters (0.25" minimum)
**Around key data:** More space = more importance

❌ Cramped slides signal insecurity about the content
✅ Generous space signals confidence and clarity

## Typography

### Size Hierarchy

| Element | Minimum Size | Recommended |
|---------|--------------|-------------|
| Headlines | 28pt | 32-36pt |
| Key data/callouts | 24pt | 28-32pt |
| Body text | 18pt | 20-24pt |
| Bullet points | 16pt | 18-20pt |
| Footnotes | 10pt | 12pt |

**Test:** Project at actual size. Can you read body text from 10 feet?

### Text Volume Limits

| Element | Maximum |
|---------|---------|
| Headline | 2 lines |
| Bullets per slide | 5 |
| Words per bullet | 12 |
| Body paragraphs | Avoid entirely |

If you need paragraphs, you need a document, not a slide.

## Data Visualization

### Chart Selection

Match the chart to the message:

| Message Type | Best Chart |
|--------------|------------|
| Trend over time | Line chart |
| Comparison (few items) | Bar chart |
| Comparison (many items) | Horizontal bar |
| Part of whole | Pie (2-4 slices only) or stacked bar |
| Correlation | Scatter plot |
| Distribution | Histogram |
| Progress | Gauge or progress bar |

### Chart Hygiene

**Remove:**
- Gridlines (or make them very light)
- Unnecessary legends (label directly)
- 3D effects (always)
- Chart borders
- Default colors (use brand colors)

**Add:**
- Direct data labels on key points
- Callout for the insight
- Clear axis labels

### Data Callouts

Don't make them hunt for the insight:

```
┌─────────────────────────────────────────────┐
│  Revenue Growth Accelerated in Q3           │
├─────────────────────────────────────────────┤
│                                   ┌───────┐ │
│         📈                        │ +24%  │ │
│       Chart                       │ Q3    │ │
│                                   └───────┘ │
│   Q1    Q2    Q3    Q4                      │
└─────────────────────────────────────────────┘
```

The callout box draws the eye to what matters.

## Color Usage

### Semantic Color

Use color to encode meaning:

| Color | Use For |
|-------|---------|
| Brand primary | Headlines, key data, emphasis |
| Brand secondary | Supporting elements, icons |
| Green | Positive, growth, success |
| Red | Negative, decline, warning |
| Gray | Secondary info, context |
| Black | Body text |

### Contrast Requirements

- Text on backgrounds: 4.5:1 minimum contrast ratio
- Headlines: Use brand primary on white/light backgrounds
- Data points: Ensure colorblind-safe palette

### Color Restraint

**Rule of 3:** No more than 3 colors per slide (plus grays)

Too many colors = visual noise = diluted message

## Slide Type Patterns

### Executive Summary Slide

```
┌─────────────────────────────────────────────┐
│  [Recommendation in one sentence]           │
├─────────────────────────────────────────────┤
│                                             │
│  • Key point 1 with specific outcome        │
│                                             │
│  • Key point 2 with specific outcome        │
│                                             │
│  • Key point 3 with specific outcome        │
│                                             │
│  → Ask: [Specific decision/approval needed] │
│                                             │
└─────────────────────────────────────────────┘
```

### Comparison Slide

```
┌─────────────────────────────────────────────┐
│  [Headline asserting which option wins]     │
├────────────────────┬────────────────────────┤
│                    │                        │
│   Option A         │    Option B            │
│   ───────          │    ───────             │
│   Pro 1            │    Pro 1               │
│   Pro 2            │    Pro 2               │
│   Con 1            │    Con 1               │
│                    │                        │
│   [Dim styling]    │   [Bold/highlighted]   │
│                    │                        │
└────────────────────┴────────────────────────┘
```

Visual treatment signals the recommendation: highlight the preferred option.

### Timeline/Roadmap Slide

```
┌─────────────────────────────────────────────┐
│  [Headline: What happens when]              │
├─────────────────────────────────────────────┤
│                                             │
│  Phase 1    ─────►  Phase 2   ─────►  Phase 3 │
│  [Q1-Q2]           [Q3-Q4]           [2026]   │
│                                             │
│  ● Milestone       ● Milestone     ● Outcome │
│  ● Milestone       ● Milestone              │
│                                             │
└─────────────────────────────────────────────┘
```

### Data-Heavy Slide

```
┌─────────────────────────────────────────────┐
│  [Headline: What the data proves]           │
├─────────────────────────────────────────────┤
│                                  ┌────────┐ │
│        ┌──────────────────┐      │ KEY    │ │
│        │                  │      │ STAT   │ │
│        │   CHART/VISUAL   │      │ +27%   │ │
│        │                  │      └────────┘ │

│                                             │
├─────────────────────────────────────────────┤
│  Source: [Citation]                         │
└─────────────────────────────────────────────┘
```

The callout box isolates the key insight. Don't make them interpret the chart.

## Icons and Graphics

### When to Use Icons

- ✅ Represent categories or concepts
- ✅ Add visual interest to text-heavy slides
- ✅ Create visual anchors in process flows
- ❌ As decoration without meaning
- ❌ When they distract from data

### Icon Principles

- Consistent style across deck (outline OR filled, not mixed)
- Same size and visual weight
- Brand colors or neutral gray
- Meaningful, not generic

### Graphics and Images

- Use high-resolution only (no pixelation)
- Ensure proper contrast with overlaid text
- Avoid stock photo clichés (handshakes, gears, puzzles)
- Consider abstract or data-based visuals instead

---

## Animation (Use Sparingly)

Animation should reveal, not entertain.

**Appropriate uses:**
- Sequential reveal of complex diagrams
- Building a narrative step-by-step
- Directing attention in data-heavy slides

**Avoid:**
- Entrance effects for every bullet
- Spinning, bouncing, or flying elements
- Transitions between every slide
- Any animation that delays understanding

**Default:** No animation. Add only if it genuinely helps comprehension.
